Reference · Git for Vibe Coding History is your debugger

The compressed version of Lesson 4. One page: the gate, the two doors, the bisect words. Pin it with the loop, sandbox, and divergence sheets.

1The time-travel gate (3 steps, in order)

1

Find the last good

git log --oneline (add --stat for the file map). Locate the checkpoint: “it was working at C.”

2

See the delta

git diff C..HEAD --stat — thirty commits, one map. Per suspicious file: git diff C..HEAD -- <file>.

3

Ask the agent, with evidence

Hand it the range diff and the failure output. Then gate its answer — as always.

Two dots = “what changed between these two commits.” On a straight line, two-dots and three-dots agree — pick one, stay consistent. Three dots on a branch name (relative-to-where-it-left-main) is the sandbox sheet’s tool.

2The two doors of undo

The guilty commit is…DoorCommand
local-only — never pushedrewindgit reset --hard <C>
pushed / sharedcancelgit revert <sha>
a whole merged feature (a --no-ff hump)cancel the humpgit revert -m 1 <merge-sha>
One question, two doors Has the bad commit left your machine? Local → rewind. Shared → cancel by a new commit. Shared history gets cancelled by new commits, never rewritten. Force-push is the fire exit, not a door.

3Bisect — the five words

WordIt says
startopen the search (refuses a dirty tree — Lesson 1’s rule again)
bad <ref>this end is broken (no ref = whatever is checked out)
good <ref>this end still works — run it to verify; a stale good anchor returns the wrong culprit
run <test-cmd>git answers for you: exit 0 = good, 125 = “can’t test this, skip it”, anything else = bad
resetclose the search; back on your branch. The guilty commit is named, not lost.

Thirty commits → about five test runs, not thirty reads. Manual version: git checks out a midpoint, you run the test, you answer bad/good. Automatic: git bisect run node test.js and watch the count shrink. Bisect is a machine — it finds the first bad commit within your anchors. Anchor hygiene is the skill.

4Agent in the archaeology

• You point, it reads, you judge. Prompt: “Here is the diff between the last known-good commit and HEAD, and here is the failure output. Which commit most plausibly caused it? Show me that commit’s diff and propose a minimal fix. Don’t change anything yet.”
• The proposed fix goes through the normal gate — Lesson 1’s diff red flags, Lesson 2’s merge-or-kill.
• Red flag (Lesson 1, recurring): the fix deletes the safety check that was raising the error. A deleted guardrail is not a fix — it’s silencing, and only you know the check was load-bearing.
• The agent can write the bisect run test — but “does it actually fail on the bug and pass on good?” is yours to verify. Full loop: you find → it reads → you gate → it fixes → you gate again.
