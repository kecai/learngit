1The remote, mapped

origin is a copy, not a boss. Your machine runs the live repo; the server holds snapshots you chose to send. Solo, it is a backup (broken-laptop insurance) and a mailbox (you-on-machine-B). Nothing syncs on its own.

push -u origin main (L2) sets the default address — bare push/pull know where to go. pull = fetch + merge: the only scary part is the merge you already know.

2Read the line; behind has two kinds

git status says…MeansMove
“up to date with 'origin/main'”copies agreenothing
“ahead by N”you hold N unsent commitsgit push
“behind by N” — no commits of yours sincestrictly behindgit pull → fast-forward: pointer slides; no merge, no conflict possible
“diverged” — both sides grewyou and the server committedgit pull → real merge → L3's two exits: finish or abort
Two exits, fourth time A pull has no exits of its own — only the diverged kind has decisions. Strictly behind is a free lunch; check the line before you pull.

3The law of push

A branch may only move forward. Rewind past a pushed commit and push → ! [rejected] (non-fast-forward): the server protects copies that don't know about your rewind. That rejection is L4's shared-history door, with a mechanism.

--force overrides it — the fire exit: never an agent, never shared history. --force-with-lease is the habit version (refuses if the server moved since your last fetch); legal only on your own private repo (L6).

4Agent at the remote

• Delegate the reading: fetch · status · log origin/main..main — agent runs freely; moves nothing you can see.
• Gate the moving: a diverged pull opens L3's exits — those are yours.
• You ship: push is the human's trigger, like the commit was in L1.
• Never: any --force. L1 guardrail + L4 “burns every clone”, cited twice.
